01. The Problem

WhatsApp Coordination Causes Data Loss & Friction

No Assignment Record

WhatsApp messages get lost in busy group chats. Unclear which rider is assigned to which package.

Zero Live Visibility

Shop owners constantly call riders mid-transit to check progress, causing safety risks and delays.

No Verified Proof

Verbal confirmations leave no digital trail or timestamped proof of completed delivery.

02. The Solution

Reflex: Role-Based Delivery Management

1. Retailer Staff

Inputs customer details, item description, and delivery address into a structured web form.

2. Dispatcher

Views incoming requests in real time and assigns available riders with a single click.

3. Boda Rider

Updates delivery status sequentially (Assigned → Picked Up → Delivered) with scan verification.

04. Trade-Off Log

Pragmatic Architectural Decisions

Decision Weak Point "Acceptable Because..." Justification
HTTP Polling 5s state update delay Prevents frequent connection drops on weak 3G/4G networks vs WebSockets.
JWT Access + Refresh Tokens No password reset flow, no server-side token revocation list Each role signs in with real credentials (phone number + password, bcrypt-hashed server-side); short-lived 15-minute access tokens limit exposure if one leaks, and a 7-day refresh token avoids forcing a re-login every 15 minutes.
Single DB Instance No cache layer (Redis) Retail shop transaction volumes do not hit concurrency bottlenecks initially.
